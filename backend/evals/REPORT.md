# QueryPilot – evaluation report

Generated by `python -m evals.summarize` from the saved run files in `backend/evals/results/`. Nothing in this file is typed by hand.

## What is measured

- **Golden set** (`evals/golden.json`, 38 cases): generation, multi-turn follow-ups, optimize, debug and guardrail cases, including the brief's own examples. **Dev split** (`evals/dev.json`, 21 harder cases).
- **Execution accuracy:** generated SQL counts as correct when its result set equals the reference SQL's result set (rows compared as multisets; column names and order ignored; row order checked only when the question asks for an ordering or top-N).
- **Held-out execution accuracy:** the same, excluding cases that mirror the brief's few-shot examples.
- **Guardrails:** destructive, out-of-scope, prompt-injection and ambiguous requests must get the expected status (refused / rejected / clarification), no SQL, and the brief's exact out-of-scope sentence.
- **Optimize:** the rewrite must validate, return the same rows as the original and carry suggestions. **Debug:** the corrected SQL must validate and match the reference result.
- Every run checks that the database file is byte-identical afterwards (the agent is read-only).

## How the prompts were tuned (honest note)

Prompt rules were tuned by inspecting failures on the **dev split**; the golden set served as a regression check. One optimize rule (keep every row when turning a subquery into a join) was added after a golden-set regression, and a rule to keep WHERE filters out of JOIN conditions was added after manual testing. Neither the golden nor the dev questions appear in the prompts' few-shot examples except the brief's own public examples. Treat these numbers as indicative: the sets are small and LLM output varies slightly between runs.

## Reproduce

```bash
# local model (Ollama)

# hosted model (needs GROQ_API_KEY)
.venv/bin/python -m evals.run_evals --provider groq --model openai/gpt-oss-120b --fast-model openai/gpt-oss-20b --out-dir evals/results/groq --save-as final
# add --golden evals/dev.json --out-dir evals/results/<provider>/dev for the dev split, then:
.venv/bin/python -m evals.summarize
```
